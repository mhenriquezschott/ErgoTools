# ErgoTools Development Workflow

This document records the local environment, GitHub workflow, and verification
steps used for this repository. It is an internal development reference.

## Visual Verification

Every changed window must be visually checked in its important populated, empty,
selected, and expanded states.

1. Use the complete `ergotools` Python environment for normal application startup
   and VTK/body-view verification in the logged-in graphical session.
2. Use `QT_QPA_PLATFORM=offscreen` only for deterministic Qt screenshots when a
   native display is not required. Offscreen screenshots can verify layout,
   clipping, charts, controls, PLOT markers, and responsive geometry, but they do
   not replace native VTK/OpenGL verification.
3. Store temporary captures under `/tmp`, not in the repository. Inspect the
   rendered image at the target window size before accepting a UI change.
4. For PLOT, verify the complete plant canvas, marker shapes, worker/job colors,
   overview tabs, filtered outcomes, gauge, highlights, and bottom controls.

## GitHub Workflow

The repository uses different fetch and push transports:

```text
fetch: https://github.com/mhenriquezschott/ErgoTools.git
push:  git@github.com:mhenriquezschott/ErgoTools.git
```

SSH authentication is configured for the `mhenriquezschott` GitHub account.
Confirm it with `ssh -T git@github.com`; GitHub reports successful authentication
and then exits because it does not provide shell access.

Before committing:

```bash
git -c safe.directory="$PWD" status --short
git -c safe.directory="$PWD" diff --stat
```

Stage only the files belonging to the current milestone. The working tree often
contains test databases, generated bytecode, local assets, and experiments that
must not be included accidentally.

Create and publish a recoverable backup before a major schema or UI phase:

```bash
git -c safe.directory="$PWD" branch backup/<descriptive-name> <commit>
git -c safe.directory="$PWD" push origin backup/<descriptive-name>
```

Commit and push the working branch after tests and visual checks pass:

```bash
git -c safe.directory="$PWD" commit -m "<milestone description>"
git -c safe.directory="$PWD" push -u origin ergotools-plot-new-ui
```

Verify synchronization explicitly:

```bash
git -c safe.directory="$PWD" fetch origin ergotools-plot-new-ui
git -c safe.directory="$PWD" status -sb
git -c safe.directory="$PWD" rev-list --left-right --count \
  origin/ergotools-plot-new-ui...HEAD
```

The final count must be `0 0`. A local backup branch alone is not a remote backup;
backup branches required for recovery must also be pushed to GitHub.
