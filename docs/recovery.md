# Backup and recovery

## Make a recoverable backup

Use the main Save after accepting/calculating changes in any project editor.
Closing Workers, Organization, Jobs, PLOT or JROT retains accepted edits privately;
there are no separate project Save controls in those windows. Project > Backup copies persisted data only; it excludes raw
pending input, unsaved drafts and in-memory Undo histories. It leaves the current
location, selection and preferences unchanged. Use a different filename; existing
destinations are not silently overwritten. A successful backup includes project
metadata, catalogs, ownership links, saved results, images, map geometry,
rotation schemes and the sole saved result for each assessment.

For a plain filesystem copy, close the application first; do not copy just the
main database file while SQLite may have an active journal. Prefer the application's
snapshot-based Backup for a project already open. Do not delete journals or edit
rows to resolve a lock. Resolve the owning process/permissions and retry.

## Restore without destroying evidence

1. Retain the current file under another name before recovery.
2. Open a separately named backup through Project > Open.
3. Check project name, workers/organization/jobs and exact worker/context/tool.
4. Check LiFFT/DUET/ST inputs and saved result status/units, PLOT image and marker
   positions, and JROT schemes/frozen profiles. Do not recalculate merely to view
   saved results; Calculate/Save replaces the sole result for that version.
5. Use Save As for a new working file after verification. Retain the backup.

Format-15 .ergprj files contain all images and one calculated result per assessment; no copied
legacy sidecars are needed to reopen them. An original XML .ergprj file still needs
its descriptor-relative database/data and image folders until conversion. Preserve
all originals and convert to a new destination; do not rewrite the original DB.

## Errors and preferences

Failed writes roll back their transaction and retain draft intent. A separately
approved Save before a Move may already have committed even if Transfer later
fails. Reopen a separate backup to verify persisted state rather than guessing.
Conversion conflicts/missing assets/newer formats require review of the reported
source; no assessment is silently skipped. Keep error text and the untouched
source set. Keep the original source files as external reference evidence; the new project
contains no original database archive or second imported-result set.

Preferences are separate JSON. The delivered launcher uses Qt's per-user
application configuration directory; --settings selects an explicit file. The
diagnostic bootstrap alone defaults to .cache/desktop_settings.json.
Back it up separately if language/units/decimal/recent paths/camera preferences
matter. Settings warnings do not imply project-data loss. Help's platform cache
contains published guides, not projects, and may be regenerated by opening Help.

project. The approved M12 clean-install/offline evidence remains valid; M5 additionally
verified current installed-wheel relocation, exact Save As/Backup and reopening.
Windows/macOS VM recovery acceptance remains deferred. Never replace the reference

UI formatting/gauge limits do not round stored values. The regenerated comprehensive

## Guided original-project upgrade — cleanup M2

Opening an earlier project explains why it needs an upgrade and offers **Migrate**
or **Cancel** (English/Spanish). It also shows a copyable command for the separate
utility. Migrate runs that external process; no converter code enters the app.
Keep original database/image folders together until conversion succeeds. Missing
tools/assets, unsupported schemas or invalid data leave the current workspace open
and show the tool error. Cancel does not start conversion. No automatic retry.

The converted project opens in temporary native storage. Use the main **Save**
action, choose a new `.ergprj` file and confirm the prefilled project details.
Original date/language/default units are retained; current display units/language
do not reinterpret task data. Cancelled/failed first Save keeps the temporary copy
open for retry. Closing/switching asks Save/Discard/Cancel even when its current
assessment is clean. Discard removes the temporary copy. An application/system
crash before first Save can lose that temporary copy; the original remains intact.

Temporary files never enter Recent Projects. After first Save, only the permanent
native file is needed: it embeds every plant image and all supported data, including
PLOT/JROT relationships. The ordinary New-project pre-save restrictions are reused;
Save first before management/PLOT/JROT/export. During this temporary stage the
existing New-project header says no project loaded; the bottom message explicitly
identifies the upgraded copy and requests Save. No unrelated header redesign.

For command-line conversion instead of the GUI:

```sh
.venv/bin/python tools/project_migration/migrate_project.py "/path/original.ergprj" --output "/path/new_project.ergprj"
```

The CLI publishes directly to its explicit new destination. For installed-wheel
users, retain the separately supplied `tools/project_migration` folder and invoke
its script with the approved environment, or expose an `ergotools-migrate` wrapper
on PATH forwarding the same arguments. The app detects that optional command;
without a tool it still opens all current native projects. Do not reinstall or
upgrade dependencies to run the converter. See its README for supported formats.

Current fixtures: `test_projects/native/comparative_risk_test.ergprj` and
`test_projects/native/integrated_test.ergprj`. Originals and sidecars are separate
byte-identical reference copies in `test_projects/originals`. The two other original
samples still have documented schema/metadata limitations; no repair was added.
Cleanup M4/M5 are complete; the native fixtures are ready for owner testing.


## Shared project history

Record deletion and other accepted project actions are reversible during the open
project session. Replays removing records ask confirmation; restoration and ordinary
field/navigation replay do not. Main Save preserves Undo/Redo. Closing/switching the
project clears that transient history; Backup remains necessary for later recovery.
Unsaved session data is held in private memory, so a process/system crash can lose it
while the last saved project remains intact. No automatic backups are created.
See [single project Save](single_project_save.md).
